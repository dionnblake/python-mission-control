# Windows desktop host

## Purpose
Host the local React application, persist the learner's progress and execute the bundled controlled CPython helper.

## Ownership
`src/storage.rs` owns transactional SQLite persistence and preservation on invalid data. `src/runner.rs` owns subprocess limits and trace parsing. `src/lib.rs` exposes only narrow Tauri commands. `tauri.conf.json` owns Windows packaging.

## Local Contracts
- Keep the native window resizable and maximizable. Default content size is 1200 by 800 logical pixels; allow resizing down to 360 by 480 so smaller windows use the responsive interface.
- Renderer commands are `load_progress`, `save_progress`, `reset_progress`, `run_trace` and read-only `runtime_info`. `reset_progress` is only for the confirmed master reset and atomically replaces the current snapshot while removing recovery data. Do not expose arbitrary filesystem paths, shell commands or unrestricted execution.
- Store the versioned progress JSON in the OS application-data directory's `progress.sqlite3`. Each save transaction keeps the preceding valid snapshot. Invalid or corrupt saved data must produce an error and must not be overwritten silently.
- Reserve each profile before creating renderer windows with an exclusive OS handle to `profile.lock`, held in managed state for the application lifetime. A second instance of the same profile must show an actionable startup error through load/save IPC and cannot access its progress. Retry may acquire ownership after the first instance closes; successful ownership is never released while that app is running. Distinct isolated profiles remain independent. The marker may remain on disk after exit; ownership depends on the live handle, so crashes do not create stale locks.
- A missing current snapshot with any retained recovery snapshot is corruption, not a fresh profile. Both load and save must preserve that recovery data and fail visibly.
- An explicit `PMC_PROFILE_DIR` startup environment variable selects an absolute local directory for a test or portable profile. Its `progress.sqlite3` and `webview/main/` are isolated from the normal learner profile. Reject relative, traversal, network, device and drive-root paths. This is a native startup option only, never a renderer-supplied path or IPC permission.
- Run helpers off the UI thread with hidden Windows consoles, bounded input/output and a hard deadline. Kill and reap on timeout.
- Release execution uses the bundled `mission-python/mission-python.exe` and its CPython DLLs. A developer Python installation is only permitted as a debug-build fallback.
- Bundled resources are generated by `npm run bundle:python`, ignored by Git, and included in the release. No runtime download, account, key or network dependency.
- Windows must have Microsoft Edge WebView2 Runtime installed. The installer does not download a runtime; Windows 11 normally includes it.
- CSP permits local assets and Tauri IPC only. Do not add shell, HTTP or filesystem plugins.

## Work Guidance
Source changes belong here. Generated Rust targets remain under `target/`; generated Python resources under `resources/`. Finished Windows packages and verification evidence are retained in the root `outputs/` directory by the release workflow.

## Verification
Run `cargo test --manifest-path src-tauri/Cargo.toml`, including real helper process, malformed protocol, hard timeout, output cap and persistence restart/corruption tests. Build the Windows package, verify bundled helper execution, and exercise progress across a desktop restart.
